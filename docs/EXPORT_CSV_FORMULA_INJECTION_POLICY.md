# ZAMORIN CAFÉ ERP — CSV & SPREADSHEET FORMULA INJECTION DEFENSE POLICY

**Policy Identifier**: `SEC-POL-EXPORT-028`  
**Version**: `2.1.0-FINAL`  
**Effective Date**: `August 2026`  
**Scope**: All CSV, TSV, and OpenXML Excel (`.xlsx`) export channels across Backend and Frontend modules.

---

## 1. Threat Model & Target Use Contexts

Spreadsheet Formula Injection (CWE-1236, also known as Dynamic Data Exchange (DDE) Injection or CSV Injection) occurs when untrusted user input contains characters that spreadsheet applications (such as Microsoft Excel, LibreOffice Calc, Google Sheets, or Apple Numbers) interpret as formula execution commands upon opening a CSV or spreadsheet file.

### Dual-Use Target Classification

| Use Context | Purpose | Primary Risk | Defense Applied |
| :--- | :--- | :--- | :--- |
| **`HUMAN_SPREADSHEET_EXPORT`** | Operators, accountants, and executives downloading reports, ledger transactions, and audit trails for manual inspection in desktop spreadsheet applications. | Execution of malicious macros, DDE payloads, external link references, or arbitrary system commands (`cmd|' /C ...'`). | **Single-Quote Neutralization (`'`)** on all trigger prefixes (`=`, `+`, `-`, `@`, `\t`, `\r`, `\n`, `＝`, `＋`, `－`, `＠`) + RFC 4180 standard quoting. |
| **`MACHINE_DATA_EXCHANGE`** | Programmatic ingestion of exported CSVs by downstream batch parsers, ETL pipelines, and API clients. | Data distortion caused by improper escaping, field delimiter splits, or unexpected quote truncation. | Strict RFC 4180 encapsulation (embedded quotes doubled as `""`, fields containing commas, semicolons, or newlines wrapped in `""`). |

## 2. Canonical Sanitization Contract

The canonical sanitization routine is implemented in `backend/src/utils/exportGenerators.js` (`sanitizeCsvValue`):

```javascript
function sanitizeCsvValue(val) {
  if (val === null || val === undefined) return '';
  let str = String(val);
  
  // 1. Formula Trigger Neutralization
  if (/^[=+\-@\t\r\n\uFF1D\uFF0B\uFF0D\uFF20]/.test(str)) {
    str = `'${str}`;
  }
  
  // 2. RFC 4180 Delimiter & Special Character Escaping
  if (str.includes('"') || str.includes(',') || str.includes(';') || str.includes('\n') || str.includes('\r')) {
    return `"${str.replace(/"/g, '""')}"`;
  }
  return str;
}
```

### Protected Character Matrix

| Trigger Prefix | Description | Attack Vector / Behavior in Desktop Apps | Defense Result |
| :---: | :--- | :--- | :--- |
| `=` | Equals sign | Standard formula trigger (e.g. `=1+1`, `=HYPERLINK(...)`, `=cmd\|...`) | Prepended with `'` -> `'=1+1` (treated as text) |
| `+` | Plus sign | Mathematical formula / implicit coercion (e.g. `+SUM(A1:A10)`) | Prepended with `'` -> `'+SUM(...)` |
| `-` | Minus sign | Mathematical formula / negative expressions (e.g. `-2+3+cmd\|...`) | Prepended with `'` -> `'-2+3` |
| `@` | Commercial At | Function call trigger in legacy Excel & Lotus (e.g. `@SUM(...)`) | Prepended with `'` -> `'@SUM(...)` |
| `\t` | Tab character | Preceding whitespace bypass before `=` in older parsers | Prepended with `'` -> `'\t...` |
| `\r` / `\n` | Carriage Return / Line Feed | Multiline formula injection or header split | Prepended with `'` and enclosed in `""` |
| `\uFF1D` (`＝`) | Full-Width Equals | Unicode normalization bypass in localized spreadsheet apps | Prepended with `'` -> `'＝1+1` |
| `\uFF0B` (`＋`) | Full-Width Plus | Unicode normalization bypass | Prepended with `'` -> `'＋SUM(...)` |
| `\uFF0D` (`－`) | Full-Width Hyphen | Unicode normalization bypass | Prepended with `'` -> `'－100` |
| `\uFF20` (`＠`) | Full-Width At | Unicode normalization bypass | Prepended with `'` -> `'＠SUM(...)` |

## 3. Delimiter & Quote Injection Resistance

Attackers frequently attempt to inject raw quotes (`"`) followed by a comma and a formula prefix (e.g. `test",=1+1,"`) to escape cell boundaries and create executable formula cells in subsequent columns.

* **Defense**: When untrusted data contains double quotes, all internal double quotes are strictly doubled (`""`), and the entire string is enclosed in an outer pair of double quotes:
  - Input: `Safe Description",=1+1,"Tail`
  - Output: `"Safe Description"",=1+1,""Tail"`
* In the output CSV, the entire value remains within a single column cell. The formula prefix does not appear at the start of any new cell.

## 4. OpenXML Excel (`.xlsx`) Formula Isolation

For binary OpenXML `.xlsx` exports generated by `generateXlsx`:

1. **Explicit Type Separation**:
   - User-supplied text is stored in the Shared String Table (`xl/sharedStrings.xml`) and referenced as `<c t="s"><v>[Index]</v></c>`.
   - Pure numeric values (numbers, prices, quantities) are stored as `<c t="n"><v>[Value]</v></c>`.
2. **Formula Node Ban for Untrusted Data**:
   - The application **never** generates formula nodes (`<f>...</f>`) from user-controlled inputs.
   - Any string value starting with `=`, `+`, `@`, or `-` is safely stored as a string literal in the shared string table (`<si><t>=1+1</t></si>`), preventing calculation execution upon workbook opening.
